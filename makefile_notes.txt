==========================================================
  מדריך זכירה: יצירת Makefile (כמו ב-Lab2)
==========================================================

מה זה Makefile?
---------------
קובץ בשם Makefile (בלי סיומת, M גדולה) שמסביר ל-make איך לבנות את התוכנית.
make מקמפל מחדש רק קבצים שהשתנו, ולכן חוסך זמן.

----------------------------------------------------------
שלב 1: להכין את הקבצים
----------------------------------------------------------
לכל מודול יש קובץ .c וקובץ .h (למשל arrays.c + arrays.h).
קובץ אחד מכיל main (ב-Lab2 זה prog.c).
כל קבצי ה-.c וה-.h צריכים להיות באותה תיקייה.

----------------------------------------------------------
שלב 2: לברר תלויות עם gcc -MM
----------------------------------------------------------
בתיקיית הפרויקט מריצים:

    gcc -MM *.c

הפלט מראה לכל קובץ .o ממה הוא תלוי (ה-.c וכל ה-.h שהוא עושה להם include).
בדוגמה של Lab2 הפלט היה:

    arrays.o: arrays.c arrays.h
    exe.o: exe.c exe.h arrays.h lab2.h
    lab2.o: lab2.c lab2.h arrays.h
    prog.o: prog.c exe.h

את השורות האלה מעתיקים כמו שהן לתוך ה-Makefile (שלב 3).
שים לב: הפקודה מדפיסה למסך בלבד, היא לא יוצרת קבצים.
טיפ: gcc -MM *.c > deps.txt  שומר את הפלט לקובץ, ואז אפשר להעתיק.
(-MM מתעלם מקבצי header של המערכת כמו stdio.h; -M היה כולל גם אותם.)

----------------------------------------------------------
שלב 3: לכתוב את ה-Makefile
----------------------------------------------------------
יוצרים קובץ בשם Makefile (למשל: touch Makefile ואז עורכים ב-VS Code / nano)
ומכניסים את התוכן הבא (זה ה-Makefile האמיתי של Lab2):

    CC = gcc
    OBJS = arrays.o exe.o lab2.o prog.o
    EXEC = myLab2
    DEBUG = -g
    CFLAGS = -Wall -Werror $(DEBUG)

    $(EXEC) : $(OBJS)
    <TAB>$(CC)  $(OBJS) -o $@

    arrays.o: arrays.c arrays.h
    exe.o: exe.c exe.h arrays.h lab2.h
    lab2.o: lab2.c lab2.h arrays.h
    prog.o: prog.c exe.h

    clean:
    <TAB>rm -f $(OBJS) $(EXEC)

הסבר על כל חלק:
  CC       = הקומפיילר (gcc)
  OBJS     = רשימת כל קבצי ה-.o (חייבים להתאים לקבצי ה-.c)
  EXEC     = שם קובץ ההרצה שייווצר
  DEBUG    = -g  מוסיף מידע דיבאג (ל-gdb ול-valgrind)
  CFLAGS   = דגלים לקומפילציה: -Wall כל האזהרות, -Werror אזהרה = שגיאה
  $(EXEC) : $(OBJS)   שורת הקישור (linking): מחבר את כל ה-.o לקובץ הרצה
  $@       = שם המטרה (ה-target), כאן myLab2
  שורות ה-.o   = התלויות שהעתקנו מ-gcc -MM
  clean    = מוחק את קבצי ה-.o ואת קובץ ההרצה

מה שחשוב לזכור:
  * לפני כל פקודה (שורה שמבצעת משהו) חייב להיות TAB אמיתי, לא רווחים!
    אחרת תקבל: "*** missing separator. Stop."
  * שורות ה-.o בלי פקודה מתחתן - make יודע לבד לקמפל .c ל-.o
    (הוא משתמש ב-CC וב-CFLAGS שהגדרנו).
  * המטרה הראשונה בקובץ היא ברירת המחדל כשמריצים make בלי ארגומנטים,
    ולכן שורת ה-$(EXEC) חייבת להיות ראשונה.
  * אחרי שמוסיפים/משנים include בקובץ, להריץ שוב gcc -MM *.c ולעדכן שורות.
  * אם מוסיפים קובץ .c חדש - להוסיף את ה-.o שלו ל-OBJS.

----------------------------------------------------------
שלב 4: להריץ
----------------------------------------------------------
    make            # בונה את התוכנית (myLab2)
    ./myLab2        # מריץ אותה
    make clean      # מוחק קבצי .o ואת קובץ ההרצה
    make -n         # מציג מה היה קורה בלי להריץ באמת (dry run)
    make -B         # כופה בנייה מחדש של הכול
    make arrays.o   # בונה רק קובץ אחד

----------------------------------------------------------
פקודות שימושיות לזכור
----------------------------------------------------------
    gcc -MM *.c                  תלויות לכל קבצי ה-c
    gcc -Wall -Werror -g -c x.c  קומפילציה ידנית של קובץ אחד ל-x.o
    gcc a.o b.o -o prog          קישור ידני של קבצי .o
    ls                           לראות קבצים בתיקייה
    cat Makefile                 להציג את ה-Makefile
    cat -A Makefile              בודק שיש TAB (יופיע כ-^I) ולא רווחים
    valgrind ./myLab2            בדיקת דליפות זיכרון (יש ב-Dockerfile שלך)
    valgrind --leak-check=full ./myLab2
    gdb ./myLab2                 דיבאג (דורש קומפילציה עם -g)

----------------------------------------------------------
Docker (מה שיש לך בתיקיית C)
----------------------------------------------------------
ב-Dockerfile שלך יש Ubuntu עם gcc, make ו-valgrind. להרצה:
    docker compose run --rm <שם-השירות> bash    (השם מופיע ב-docker-compose.yml)
ואז בתוך הקונטיינר, בתיקיית /workspace, מריצים make וכו'.

----------------------------------------------------------
שגיאות נפוצות
----------------------------------------------------------
  missing separator           -> השתמשת ברווחים במקום TAB
  No rule to make target X    -> שגיאת כתיב בשם קובץ ב-OBJS או בתלויות
  undefined reference to ...  -> חסר .o ב-OBJS או חסר קובץ .c
  multiple definition of main -> יש שני קבצים עם main ב-OBJS
  make: 'x' is up to date     -> שום דבר לא השתנה; אפשר make clean ואז make

----------------------------------------------------------
צ'קליסט מהיר לפרויקט חדש
----------------------------------------------------------
  1. gcc -MM *.c
  2. ליצור Makefile: CC, OBJS, EXEC, DEBUG, CFLAGS
  3. שורת קישור (עם TAB) + שורות התלויות מ-gcc -MM
  4. clean
  5. make  ->  ./EXEC  ->  make clean
